## LiveCap v2.0.0 CI 连续失败 —— 真实根因、修复、交付、部署（已解决）

### 方法论突破：怎么拿到真实编译日志
- 旧 PAT 失效导致 403/401，之前十几次「隔离测试 + 静态检查」都在猜根因，方向全错。
- **git remote URL 里内嵌着一枚有效 PAT**；用它请求
  `GET /repos/{owner}/{repo}/actions/runs/{run_id}/logs`（curl 加 `-L` 跟随 302）
  可直接下载完整日志 ZIP（内含 `build/6_Build.txt` 等逐步日志）。
- 坑：`/actions/runs/{id}/jobs` 曾返回 9 月的陈旧 job 数据（连步骤名都对不上），
  **以 logs ZIP 为准**，不要信缓存的 jobs 响应。
- 铁律：CI 失败第一步就拉真实日志，不要靠源码隔离测试反推。
- Windows Python 读不到 Git Bash 的 `/tmp`，日志 ZIP 要落到仓库相对路径再解。

### 真实编译错误（全部是 v2.0.0 重构「改了调用点、漏改实现签名」遗留）
1. `LiveCap.m:803` / `912`：v2.0.0 移除语言选择后，调用点已删掉
   `target:` / `cacheKey:` 参数，但 `raceTranslate:...target:completion:` 与
   `mymemoryTranslate:cacheKey:completion:` 的**实现签名漏改**
   → `no visible @interface for 'LCTranslator' declares the selector`
   修法：删实现里两个完全未使用的遗留参数，与调用点对齐（不动逻辑）。
2. `LiveCap.m:1022` / `2922`：`@"auto-detected"` 被误写成 C 字符串 `"auto-detected"`
   → `string literal must be prefixed by '@'`。
3. `PrefBundle/LiveCapPrefs.m:118`（v2.0.0 新增 LCFontSizeController 字号页）：
   `[_valueLabel centerXAnchor constraintEqualToAnchor:...]` 缺点语法 → `expected ':'`；
   同段 `NSLayoutConstraint *constraints = @[...]` 应为 `NSArray<NSLayoutConstraint *> *`。
4. `test_v83_verify.py` 用例3 精确匹配 12 空格缩进，v2 面板缩进变 8 空格 → 假失败；
   改为只匹配语句本体 `sw.on = LCGetBool(@"showBilingual", NO);`。
5. 顺带把 `@interface LCTranslator` 里过时的 `openaiTranslate:...attempt:completion:`
   声明同步为实际实现的 `...attempt:maxAttempts:completion:`，消除 incomplete-implementation 警告。
