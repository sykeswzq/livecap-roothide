## LiveCap v2.0.0 CI 连续失败 —— 真实根因、修复、交付、部署（已解决）

### 方法论突破：怎么拿到真实编译日志
- 旧 PAT 失效导致 403/401，之前十几次「隔离测试 + 静态检查」都在猜根因，方向全错。
- **git remote URL 里内嵌着一枚有效 PAT**；用它请求
  `GET /repos/{owner}/{repo}/actions/runs/{run_id}/logs`（curl 加 `-L` 跟随 302）
  可直接下载完整日志 ZIP（内含 `build/6_Build.txt` 等逐步日志）。
- 坑：`/actions/runs/{id}/jobs` 曾返回 9 月的陈旧 job 数据（连步骤名都对不上），
  **以 logs ZIP 为准**，不要信缓存的 jobs 响应。
- 铁律：CI 失败第一步就拉真实日志，不要靠源码隔离测试反推。
- Windows Python 读不到 Git Bash 的 `/tmp`，日志 ZIP 要落到仓库相对路径再解。

2. `LiveCap.m:1022` / `2922`：`@"auto-detected"` 被误写成 C 字符串 `"auto-detected"`
   → `string literal must be prefixed by '@'`。
3. `PrefBundle/LiveCapPrefs.m:118`（v2.0.0 新增 LCFontSizeController 字号页）：
   `[_valueLabel centerXAnchor constraintEqualToAnchor:...]` 缺点语法 → `expected ':'`；
   同段 `NSLayoutConstraint *constraints = @[...]` 应为 `NSArray<NSLayoutConstraint *> *`。
4. `test_v83_verify.py` 用例3 精确匹配 12 空格缩进，v2 面板缩进变 8 空格 → 假失败；
   改为只匹配语句本体 `sw.on = LCGetBool(@"showBilingual", NO);`。

## 追加（14:25）：v2.0.1 延迟优化（用户反馈「2.5s 延迟高、慢一拍」）
### 诊断：日志位置与实测数据
- 设备日志实际写在 **App 沙盒**：
  `/var/mobile/Containers/Data/Application/<UUID>/Documents/livecap.log`
  （代码里尽力写的全局 `/var/mobile/Documents/livecap.log` 在沙盒下写不进去，别去那儿找）
- 用 `grep -E 'overlay: (pending|showPair|showFailed) seq='` + `asr: rtt=` 配对时间戳即可量化。
- 实测：分片 2.57s、ASR RTT 平均 985ms（552~3967ms）、
  当前会话中文上屏滞后 5~8s 且**越积越多**、40 句里 21 句没中文。

### 根因（不是分片时长）
- `LCTranslator` 是严格串行 FIFO（`_inflight` 单槽 + `kMaxQueue=3`），
  ASR 每 2.5s 入队一句，agnes 单次 0.87~3.4s（偶发 7.6s）→ 入队快于出队 → 积压 2~3 句。
- **`mymemoryTranslate` 用 `langpair=auto|zh-CN`，MyMemory 返回 403
  `'AUTO' IS AN INVALID SOURCE LANGUAGE`** → 免费兜底 100% 失败，竞速实际只有 agnes 一家。
- `openaiTranslate` 的 `req.timeoutInterval = 30.0`：**竞速全部失败时**
  `_inflight` 要等最慢一路超时才释放，30s 直接把队列堵死 → 大量 `showFailed`。
- 注意：`raceTranslate` 第一个有效译文返回就会调 completion 释放 `_inflight`，
  慢的 provider 不占队列；只有「全失败」才卡住。
- 调用点本来就有 seq 对账（`showPair`/`showFailed` 会丢弃迟到旧译文），渲染层无需改。
- **结论：缩短分片会让入队更快、积压更严重**，必须先疏通翻译侧。

### 修复（5 处，全在 LiveCap.m；版本 2.0.1）
1. MyMemory `src = @"auto"` → `@"en"`（403 消失，白捡 1.2~2.4s 快速兜底）
2. `mymemoryTranslate` / `tencentTranslate` 超时 12→6s
3. `openaiTranslate` 超时 30→6s（最坏 6s 释放队列）
4. `kMaxQueue` 3→1（只留最新一句，旧句回调 nil；宁可偶尔缺句也不滞后）
5. `pumpQueue` 加 `translate: inflight rtt=...ms len=...` 日志，便于下次量化
- 版本号三处同步：`build.sh VER`、`PrefBundle/Info.plist` 两个字段、`postinst` 注释。
- ASR 侧超时（`cfg.timeoutIntervalForRequest=12.0`、ASR req 10.0）**不动**（ASR 有 4s 长尾）。
