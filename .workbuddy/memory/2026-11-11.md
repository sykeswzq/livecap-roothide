## XL 已验证可用的注入做法（5 条）
1. **勾选状态真相 = 偏好 plist**（`apps` 键），面板 UI 绝不从 Filter plist 回读；
   `XLSetValue` 写文件 + CFPreferences + `notify_post`。
2. **写完 Filter.Bundles 立刻 `killall runningboardd`**（`XLWriteFilterBundles` 内 posix_spawn
   `/usr/bin/killall`）——不刷新注入框架缓存，改了 plist 也要注销才生效。
3. **Filter plist 必须 666**：build.sh 打包时 chmod 666 + postinst 再 chmod 666，
   且 postinst 用 `$(dirname "$0")/../../...` 与相对 CWD 两条路径，不硬编码 `/var/jb`。
4. **dylib 运行时完全不做 App 白名单判定**，constructor 只排除 /System、/usr、/bin，
   注入范围只由 Filter.Bundles 精确匹配 + Dopamine Inject Manager 决定。
5. README/面板明写「真皮白名单里允许注入 + 彻底退出重开生效」，不假装勾选即生效。

## v2.2.0「选其他 App 无效」的真正根因（4 条）
1. `lc_selected` 从 `LCReadFilterBundles()` 回读。roothide 下该路径在「设置」进程里
   不稳定，回读为空 → 面板显示全部未勾选 → 用户勾 1 个就把打包默认 27 个 bundle
   **抹成 1 个**。
2. `LCWriteFilterBundles` 写完不刷新注入缓存（XL 有、LiveCap 没有）。
3. v2.2.0 新加的 `LCBundleAllowedByPrefs()` 硬卡「enabledBundles 非空且当前 bundle
   不在列表 → constructor 直接 return」。列表一旦被写坏，**连原本能用的 YouTube
   一起挡掉**，表现为「注入没效果 / 没字幕」。这是自己引入的回归。
4. 多候选路径遍历写入，第一条写成就 return，可能只写进影子目录；
   postinst chmod 只有硬编码 `/var/jb/...`，roothide 下可能落空。

> 注意：v2.2.0 诊断的「Filter 路径漏了 jbroot()」并非主因 —— XL 用同样的
> dyld 镜像拼路径写法却能工作。真正差别在「状态真相、刷新缓存、运行时不拦截」。
> 结论：**路径不是关键，机制才是**。

## 旧日志重大发现（Nov 10 21:48，2.2.0 时代）
- WebSocket 实时 ASR **从未握手成功**：`asr: ws code=6001`，消息为
  「请检查是否开通跨境流量...或购买跨境资源包」；每次启动重连 5 次后
  `retry exhausted -> stop, HTTP fallback takes over`。
  → v2.1.x / 2.2.x 的流式链路在真机上一直是死的，字幕全靠 HTTP 分片回落。
  这是账号 / 出口 IP 侧限制，不是签名或代码问题（本地已验证签名与握手可通）。
  设备装有 vpnplus.dylib 等代理插件，出口 IP 是否被判境外待确认。
- `translate: race -> mymemory`，原文 `Over and that is the` 对应译文「只要听一遍」
  → MyMemory 返回不相干 / 上一句内容，是「字幕和语音对不上」的直接证据。
- 日志时间停在 11-10 21:48，用户尚未用 2.2.1 重开 App，以上均为旧版本行为。
